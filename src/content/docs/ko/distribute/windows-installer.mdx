Windows용 Tauri 애플리케이션은 [WiX Toolset v3]를 사용하는 Microsoft Installer(`.msi` 파일)
또는 [NSIS]를 사용하는 설치 실행 파일(`-setup.exe` 파일)로 배포됩니다.

`.msi` 설치 프로그램은 WiX가 Windows 시스템에서만 실행될 수 있으므로 **Windows에서만 만들 수 있다**는 점에 유의하십시오.
NSIS 설치 프로그램의 크로스 컴파일은 아래에 나와 있습니다.

이 가이드는 설치 프로그램에 사용할 수 있는 사용자 지정 옵션에 대한 정보를 제공합니다.

## 빌드

앱을 빌드하고 Windows 설치 프로그램으로 번들링하려면 Tauri CLI를 사용하고 Windows 컴퓨터에서 `tauri build` 명령을 실행하면 됩니다:

<CommandTabs
  npm="npm run tauri build"
  yarn="yarn tauri build"
  pnpm="pnpm tauri build"
  deno="deno task tauri build"
  bun="bun tauri build"
  cargo="cargo tauri build"
/>

:::note[MSI 패키지에 대한 VBSCRIPT 요구 사항]

MSI 패키지 빌드(`tauri.conf.json`의 `"targets": "msi"` 또는 `"targets": "all"`)를 위해서는 Windows에서 VBSCRIPT 선택적 기능을 활성화해야 합니다. 이 기능은 대부분의 Windows 설치에서 기본적으로 활성화되어 있지만 `failed to run light.exe`와 같은 오류가 발생하면 **설정** → **앱** → **선택적 기능** → **기타 Windows 기능**을 통해 수동으로 활성화해야 할 수 있습니다. 자세한 지침은 [필수 조건 가이드](/ko/start/prerequisites/#vbscript-for-msi-installers)를 참조하십시오.

:::

### Linux 및 macOS에서 Windows 앱 빌드

Linux 및 macOS 호스트에서 Windows 앱을 크로스 컴파일하는 것은 [NSIS]를 사용할 때 주의 사항과 함께 가능합니다.
Windows에서 직접 컴파일하는 것만큼 간단하지 않으며 테스트도 많이 되지 않았습니다.
따라서 로컬 VM이나 GitHub Actions와 같은 CI 솔루션이 작동하지 않는 경우 최후의 수단으로만 사용해야 합니다.

:::note

크로스 컴파일된 Windows 설치 프로그램에 서명하려면 외부 서명 도구가 필요합니다.
자세한 내용은 [서명 문서][signing documentation]를 참조하십시오.

:::

Tauri는 공식적으로 MSVC Windows 대상만 지원하므로 설정이 조금 더 복잡합니다.

#### NSIS 설치

<Tabs syncKey="OS">
<TabItem label="Linux">
일부 Linux 배포판에는 리포지토리에 NSIS가 있습니다. 예를 들어 Ubuntu에서는 다음 명령을 실행하여 NSIS를 설치할 수 있습니다:

```sh title=Ubuntu
sudo apt install nsis
```

그러나 다른 많은 배포판에서는 NSIS를 직접 컴파일하거나 배포판의 바이너리 패키지에 포함되지 않은 Stub 및 플러그인을 수동으로 다운로드해야 합니다.
예를 들어 Fedora는 바이너리만 제공하고 Stub 및 플러그인은 제공하지 않습니다:

```sh title=Fedora
sudo dnf in mingw64-nsis
wget https://github.com/tauri-apps/binary-releases/releases/download/nsis-3/nsis-3.zip
unzip nsis-3.zip
sudo cp nsis-3.08/Stubs/* /usr/share/nsis/Stubs/
sudo cp -r nsis-3.08/Plugins/** /usr/share/nsis/Plugins/
```

</TabItem>

<TabItem label="macOS">
macOS에서는 NSIS를 설치하려면 [Homebrew]가 필요합니다:

```sh title=macOS
brew install nsis
```

</TabItem>
</Tabs>

#### LLVM 및 LLD 링커 설치

기본 Microsoft 링커는 Windows에서만 작동하므로 새 링커도 설치해야 합니다.
앱 아이콘 설정 등에 사용되는 Windows 리소스 파일을 컴파일하려면
LLVM 프로젝트의 일부인 `llvm-rc` 바이너리도 필요합니다.

<Tabs syncKey="OS">
<TabItem label="Linux">

```sh title="Ubuntu"
sudo apt install lld llvm
```

Linux에서는 빌드 스크립트의 일부로 C/C++ 종속성을 컴파일하는 종속성을 추가한 경우 `clang` 패키지도 설치해야 합니다.
기본 Tauri 앱에는 이것이 필요하지 않습니다.

</TabItem>
<TabItem label="macOS">
```sh title=macOS
brew install llvm
```

macOS에서는 설치 출력에서 제안한 대로 `/opt/homebrew/opt/llvm/bin`을 `$PATH`에 추가해야 합니다.

</TabItem>
</Tabs>

#### Windows Rust 대상 설치

64비트 Windows 시스템용으로 빌드한다고 가정합니다:

```sh
rustup target add x86_64-pc-windows-msvc
```

#### `cargo-xwin` 설치

Windows SDK를 수동으로 설정하는 대신 [`cargo-xwin`]을 Tauri의 "runner"로 사용합니다:

```sh
cargo install --locked cargo-xwin
```

기본적으로 `cargo-xwin`은 Windows SDK를 프로젝트 로컬 폴더에 다운로드합니다.
여러 프로젝트가 있고 해당 파일을 공유하려면 `XWIN_CACHE_DIR` 환경 변수를 선호하는 위치의 경로로 설정할 수 있습니다.

#### 앱 빌드

이제 `tauri build` 명령에 runner와 target을 추가하는 것만큼 간단해야 합니다:

<CommandTabs
  npm="npm run tauri build -- --runner cargo-xwin --target x86_64-pc-windows-msvc"
  yarn="yarn tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc"
  pnpm="pnpm tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc"
  deno="deno task tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc"
  bun="bun tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc"
  cargo="cargo tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc"
/>

빌드 출력은 `target/x86_64-pc-windows-msvc/release/bundle/nsis/`에 있습니다.

### 32비트 또는 ARM용 빌드

Tauri CLI는 기본적으로 머신의 아키텍처를 사용하여 실행 파일을 컴파일합니다.
64비트 머신에서 개발 중이라고 가정하면 CLI는 64비트 애플리케이션을 생성합니다.

**32비트** 머신을 지원해야 하는 경우 `--target` 플래그를 사용하여 **다른** [Rust 대상][platform support]으로 애플리케이션을 컴파일할 수 있습니다:

<CommandTabs
  npm="npm run tauri build -- --target i686-pc-windows-msvc"
  yarn="yarn tauri build --target i686-pc-windows-msvc"
  pnpm="pnpm tauri build --target i686-pc-windows-msvc"
  deno="deno task tauri build --target i686-pc-windows-msvc"
  bun="bun tauri build --target i686-pc-windows-msvc"
  cargo="cargo tauri build --target i686-pc-windows-msvc"
/>

기본적으로 Rust는 머신의 대상에 대한 툴체인만 설치하므로,
먼저 32비트 Windows 툴체인을 설치해야 합니다: `rustup target add i686-pc-windows-msvc`.

**ARM64**용으로 빌드해야 하는 경우 먼저 추가 빌드 도구를 설치해야 합니다.
이렇게 하려면 `Visual Studio Installer`를 열고 "수정"을 클릭한 다음 "개별 구성 요소" 탭에서 "C++ ARM64 빌드 도구"를 설치합니다.
이 글을 쓰는 시점에서 VS2022의 정확한 이름은 `MSVC v143 - VS 2022 C++ ARM64 build tools (Latest)`입니다.
이제 `rustup target add aarch64-pc-windows-msvc`로 rust 대상을 추가한 다음 위에서 언급한 방법을 사용하여 앱을 컴파일할 수 있습니다:

<CommandTabs
  npm="npm run tauri build -- --target aarch64-pc-windows-msvc"
  yarn="yarn tauri build --target aarch64-pc-windows-msvc"
  pnpm="pnpm tauri build --target aarch64-pc-windows-msvc"
  deno="deno task tauri build --target aarch64-pc-windows-msvc"
  bun="bun tauri build --target aarch64-pc-windows-msvc"
  cargo="cargo tauri build --target aarch64-pc-windows-msvc"
/>

:::info

NSIS 설치 프로그램 자체는 여전히 에뮬레이션을 통해 ARM 머신에서 실행되는 x86입니다. 앱 자체는 네이티브 ARM64 바이너리입니다.

:::

## Windows 7 지원

기본적으로 Microsoft Installer(`.msi`)는 WebView2 부트스트래퍼가 설치되지 않은 경우 다운로드해야 하므로 Windows 7에서 작동하지 않습니다
(운영 체제에서 TLS 1.2가 활성화되지 않은 경우 실패할 수 있음). Tauri에는 WebView2 부트스트래퍼를 임베드하는 옵션이 포함되어 있습니다
(아래의 [WebView2 부트스트래퍼 임베딩](#embedded-bootstrapper) 섹션 참조).
NSIS 기반 설치 프로그램(`-setup.exe`)은 Windows 7에서도 `downloadBootstrapper` 모드를 지원합니다.

또한 Windows 7에서 알림 API를 사용하려면 `windows7-compat` Cargo 기능을 활성화해야 합니다:

```toml title="Cargo.toml"
[dependencies]
tauri-plugin-notification = { version = "2.0.0", features = [ "windows7-compat" ] }
```

## FIPS 준수

시스템에서 MSI 번들이 FIPS를 준수해야 하는 경우 `tauri build`를 실행하기 전에 `TAURI_BUNDLER_WIX_FIPS_COMPLIANT` 환경 변수를 `true`로 설정할 수 있습니다.
PowerShell에서는 다음과 같이 현재 터미널 세션에 대해 설정할 수 있습니다:

```powershell
$env:TAURI_BUNDLER_WIX_FIPS_COMPLIANT="true"
```

## WebView2 설치 옵션

설치 프로그램은 기본적으로 WebView2 부트스트래퍼를 다운로드하고 런타임이 설치되지 않은 경우 실행합니다.
또는 부트스트래퍼를 임베드하거나, 오프라인 설치 프로그램을 임베드하거나, 고정된 WebView2 런타임 버전을 사용할 수 있습니다.
이러한 방법 간의 비교는 다음 표를 참조하십시오:

| 설치 방법                                | 인터넷 연결 필요? | 추가 설치 프로그램 크기 | 비고                                                                                                                   |
| :------------------------------------------------- | :---------------------------- | :------------------------ | :---------------------------------------------------------------------------------------------------------------------- |
| [`downloadBootstrapper`](#downloaded-bootstrapper) | 예                           | 0MB                       | `기본값` <br /> 설치 프로그램 크기가 작지만 `.msi` 파일을 통한 Windows 7 배포에는 권장되지 않습니다. |
| [`embedBootstrapper`](#embedded-bootstrapper)      | 예                           | ~1.8MB                    | `.msi` 설치 프로그램에 대한 Windows 7 지원이 더 좋습니다.                                                                      |
| [`offlineInstaller`](#offline-installer)           | 아니요                            | ~127MB                    | WebView2 설치 프로그램을 임베드합니다. 오프라인 환경에 권장됩니다.                                                        |
| [`fixedVersion`](#fixed-version)                   | 아니요                            | ~180MB                    | 고정된 WebView2 버전을 임베드합니다.                                                                                        |
| [`skip`](#skipping-installation)                   | 아니요                            | 0MB                       | ⚠️ 권장하지 않음 <br /> Windows 설치 프로그램의 일부로 WebView2를 설치하지 않습니다.                               |

:::info

Windows 10(2018년 4월 릴리스 이상) 및 Windows 11에서 WebView2 런타임은 운영 체제의 일부로 배포됩니다.

:::

### 다운로드된 부트스트래퍼

이것은 Windows 설치 프로그램 빌드를 위한 기본 설정입니다. 부트스트래퍼를 다운로드하고 실행합니다.
인터넷 연결이 필요하지만 설치 프로그램 크기가 작아집니다.
`.msi` 설치 프로그램을 통해 Windows 7에 배포하려는 경우 권장되지 않습니다.

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "webviewInstallMode": {
        "type": "downloadBootstrapper"
      }
    }
  }
}
```

### 임베드된 부트스트래퍼

WebView2 부트스트래퍼를 임베드하려면 [webviewInstallMode]를 `embedBootstrapper`로 설정하십시오.
이렇게 하면 설치 프로그램 크기가 약 1.8MB 증가하지만 Windows 7 시스템과의 호환성이 향상됩니다.

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "webviewInstallMode": {
        "type": "embedBootstrapper"
      }
    }
  }
}
```

### 오프라인 설치 프로그램

WebView2 부트스트래퍼를 임베드하려면 [webviewInstallMode]를 `offlineInstaller`로 설정하십시오.
이렇게 하면 설치 프로그램 크기가 약 127MB 증가하지만 인터넷 연결을 사용할 수 없는 경우에도 애플리케이션을 설치할 수 있습니다.

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "webviewInstallMode": {
        "type": "offlineInstaller"
      }
    }
  }
}
```

### 고정 버전

시스템에서 제공하는 런타임을 사용하는 것은 Windows에서 웹뷰 취약성 패치를 관리하므로 보안에 좋습니다.
각 애플리케이션에서 WebView2 배포를 제어하려면
(릴리스 패치를 직접 관리하거나 인터넷 연결을 사용할 수 없는 환경에 애플리케이션을 배포하기 위해)
Tauri가 런타임 파일을 번들링해 줄 수 있습니다.

:::caution

고정된 WebView2 런타임 버전을 배포하면 Windows 설치 프로그램이 약 180MB 증가합니다.

:::

1. [Microsoft 웹사이트][download-webview2-runtime]에서 WebView2 고정 버전 런타임을 다운로드합니다.
   이 예에서 다운로드된 파일 이름은 `Microsoft.WebView2.FixedVersionRuntime.128.0.2739.42.x64.cab`입니다.
2. 파일을 core 폴더에 압축 해제합니다:

```powershell
Expand .\Microsoft.WebView2.FixedVersionRuntime.128.0.2739.42.x64.cab -F:* ./src-tauri
```

3. `tauri.conf.json`에서 WebView2 런타임 경로를 구성합니다:

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "webviewInstallMode": {
        "type": "fixedRuntime",
        "path": "./Microsoft.WebView2.FixedVersionRuntime.98.0.1108.50.x64/"
      }
    }
  }
}
```

4. `tauri build`를 실행하여 고정된 WebView2 런타임이 포함된 Windows 설치 프로그램을 생성합니다.

### 설치 건너뛰기

[webviewInstallMode]를 `skip`으로 설정하여 설치 프로그램에서 WebView2 런타임 다운로드 확인을 제거할 수 있습니다.
사용자가 런타임을 설치하지 않은 경우 애플리케이션이 작동하지 않습니다.

:::warning

사용자가 런타임을 설치하지 않았고 설치를 시도하지 않으면 애플리케이션이 작동하지 않습니다.

:::

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "webviewInstallMode": {
        "type": "skip"
      }
    }
  }
}
```

## WiX 설치 프로그램 사용자 지정

사용자 지정 옵션의 전체 목록은 [WiX 구성][WiX configuration]을 참조하십시오.

### 설치 프로그램 템플릿

`.msi` Windows 설치 프로그램 패키지는 [WiX Toolset v3]를 사용하여 빌드됩니다.
현재 미리 정의된 [구성][WiX configuration] 외에도 사용자 지정 WiX 소스 코드
(`.wxs` 파일 확장자를 가진 XML 파일)를 사용하거나 WiX 조각을 통해 변경할 수 있습니다.

#### 사용자 지정 WiX 파일로 설치 프로그램 코드 교체

Tauri가 정의한 Windows 설치 프로그램 XML은 간단한 웹뷰 기반 애플리케이션의 일반적인 사용 사례에 맞게 구성되어 있습니다
([여기][default wix template]에서 찾을 수 있습니다).
이것은 [handlebars]를 사용하므로 Tauri CLI가 `tauri.conf.json` 정의에 따라 설치 프로그램을 브랜딩할 수 있습니다.
완전히 다른 설치 프로그램이 필요한 경우 [`tauri.bundle.windows.wix.template`]에서 사용자 지정 템플릿 파일을 구성할 수 있습니다.

#### WiX 조각으로 설치 프로그램 확장

[WiX 조각][WiX fragment]은 WiX가 제공하는 거의 모든 것을 구성할 수 있는 컨테이너입니다.
이 예에서는 두 개의 레지스트리 항목을 작성하는 조각을 정의합니다:

```xml
<?xml version="1.0" encoding="utf-8"?>
<Wix xmlns="http://schemas.microsoft.com/wix/2006/wi">
  <Fragment>
    <!-- these registry entries should be installed
		 to the target user's machine -->
    <DirectoryRef Id="TARGETDIR">
      <!-- groups together the registry entries to be installed -->
      <!-- Note the unique `Id` we provide here -->
      <Component Id="MyFragmentRegistryEntries" Guid="*">
        <!-- the registry key will be under
			 HKEY_CURRENT_USER\Software\MyCompany\MyApplicationName -->
        <!-- Tauri uses the second portion of the
			 bundle identifier as the `MyCompany` name
			 (e.g. `tauri-apps` in `com.tauri-apps.test`)  -->
        <RegistryKey
          Root="HKCU"
          Key="Software\MyCompany\MyApplicationName"
          Action="createAndRemoveOnUninstall"
        >
          <!-- values to persist on the registry -->
          <RegistryValue
            Type="integer"
            Name="SomeIntegerValue"
            Value="1"
            KeyPath="yes"
          />
          <RegistryValue Type="string" Value="Default Value" />
        </RegistryKey>
      </Component>
    </DirectoryRef>
  </Fragment>
</Wix>
```

`src-tauri/windows/fragments` 폴더에 `.wxs` 확장자로 조각 파일을 저장하고 `tauri.conf.json`에서 참조하십시오:

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "wix": {
        "fragmentPaths": ["./windows/fragments/registry.wxs"],
        "componentRefs": ["MyFragmentRegistryEntries"]
      }
    }
  }
}
```

`ComponentGroup`, `Component`, `FeatureGroup`, `Feature` 및 `Merge` 요소 ID는 설치 프로그램에 포함되려면
각각 `componentGroupRefs`, `componentRefs`, `featureGroupRefs`, `featureRefs` 및 `mergeRefs`의
`tauri.conf.json`의 `wix` 개체에서 참조되어야 합니다.

### 국제화

WiX 설치 프로그램은 기본적으로 `en-US` 언어를 사용하여 빌드됩니다.
국제화(i18n)는 [`tauri.bundle.windows.wix.language`] 속성을 사용하여 구성할 수 있으며,
Tauri가 설치 프로그램을 빌드해야 하는 언어를 정의합니다.
[Microsoft 웹사이트][localizing the error and actiontext tables]의 Language-Culture 열에서 사용할 언어 이름을 찾을 수 있습니다.

#### 단일 언어용 WiX 설치 프로그램 컴파일

특정 언어를 대상으로 하는 단일 설치 프로그램을 만들려면 `language` 값을 문자열로 설정하십시오:

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "wix": {
        "language": "fr-FR"
      }
    }
  }
}
```

#### 목록의 각 언어에 대한 WiX 설치 프로그램 컴파일

언어 목록을 대상으로 하는 설치 프로그램을 컴파일하려면 배열을 사용하십시오.
언어 키를 접미사로 사용하여 각 언어에 대한 특정 설치 프로그램이 생성됩니다:

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "wix": {
        "language": ["en-US", "pt-BR", "fr-FR"]
      }
    }
  }
}
```

#### 각 언어에 대한 WiX 설치 프로그램 문자열 구성

각 언어에 대해 구성 개체를 정의하여 현지화 문자열을 구성할 수 있습니다:

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "wix": {
        "language": {
          "en-US": null,
          "pt-BR": {
            "localePath": "./wix/locales/pt-BR.wxl"
          }
        }
      }
    }
  }
}
```

`localePath` 속성은 언어 파일의 경로를 정의하며, 언어 문화를 구성하는 XML입니다:

```xml
<WixLocalization
  Culture="en-US"
  xmlns="http://schemas.microsoft.com/wix/2006/localization"
>
  <String Id="LaunchApp"> Launch MyApplicationName </String>
  <String Id="DowngradeErrorMessage">
    A newer version of MyApplicationName is already installed.
  </String>
  <String Id="PathEnvVarFeature">
    Add the install location of the MyApplicationName executable to
    the PATH system environment variable. This allows the
    MyApplicationName executable to be called from any location.
  </String>
  <String Id="InstallAppFeature">
    Installs MyApplicationName.
  </String>
</WixLocalization>
```

:::note

`WixLocalization` 요소의 `Culture` 필드는 구성된 언어와 일치해야 합니다.

:::

현재 Tauri는 `LaunchApp`, `DowngradeErrorMessage`, `PathEnvVarFeature` 및 `InstallAppFeature` 로케일 문자열을 참조합니다.
사용자 지정 템플릿이나 조각에서 `"!(loc.TheStringId)"`를 사용하여 고유한 문자열을 정의하고 참조할 수 있습니다.
자세한 내용은 [WiX 현지화 문서][WiX localization documentation]를 참조하십시오.

## NSIS 설치 프로그램 사용자 지정

사용자 지정 옵션의 전체 목록은 [NSIS 구성][NSIS configuration]을 참조하십시오.

### 설치 프로그램 템플릿

Tauri가 정의한 NSIS 설치 프로그램의 `.nsi` 스크립트는 간단한 웹뷰 기반 애플리케이션의 일반적인 사용 사례에 맞게 구성되어 있습니다
([여기][default nsis template]에서 찾을 수 있습니다).
이것은 [handlebars]를 사용하므로 Tauri CLI가 `tauri.conf.json` 정의에 따라 설치 프로그램을 브랜딩할 수 있습니다.
완전히 다른 설치 프로그램이 필요한 경우 [`tauri.bundle.windows.nsis.template`]에서 사용자 지정 템플릿 파일을 구성할 수 있습니다.

### 설치 프로그램 확장

일부 설치 단계만 확장해야 하는 경우 전체 설치 프로그램 템플릿을 교체하는 대신 설치 프로그램 후크를 사용할 수 있습니다.

지원되는 후크는 다음과 같습니다:

- `NSIS_HOOK_PREINSTALL`: 파일 복사, 레지스트리 키 값 설정 및 바로 가기 생성 전에 실행됩니다.
- `NSIS_HOOK_POSTINSTALL`: 설치 프로그램이 모든 파일 복사, 레지스트리 키 설정 및 바로 가기 생성을 완료한 후 실행됩니다.
- `NSIS_HOOK_PREUNINSTALL`: 파일, 레지스트리 키 및 바로 가기를 제거하기 전에 실행됩니다.
- `NSIS_HOOK_POSTUNINSTALL`: 파일, 레지스트리 키 및 바로 가기가 제거된 후 실행됩니다.

예를 들어 `src-tauri/windows` 폴더에 `hooks.nsh` 파일을 만들고 필요한 후크를 정의합니다:

```nsh
!macro NSIS_HOOK_PREINSTALL
  MessageBox MB_OK "PreInstall"
!macroend

!macro NSIS_HOOK_POSTINSTALL
  MessageBox MB_OK "PostInstall"
!macroend

!macro NSIS_HOOK_PREUNINSTALL
  MessageBox MB_OK "PreUnInstall"
!macroend

!macro NSIS_HOOK_POSTUNINSTALL
  MessageBox MB_OK "PostUninstall"
!macroend
```

그런 다음 해당 후크 파일을 사용하도록 Tauri를 구성해야 합니다:

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "nsis": {
        "installerHooks": "./windows/hooks.nsh"
      }
    }
  }
}
```

#### 후크를 사용한 종속성 설치

설치 프로그램 후크를 사용하여 애플리케이션에 필요한 시스템 종속성을 자동으로 설치할 수 있습니다. 이것은 Visual C++ Redistributables, DirectX, OpenSSL 또는 모든 Windows 시스템에 존재하지 않을 수 있는 기타 시스템 라이브러리와 같은 런타임 종속성에 특히 유용합니다.

**MSI 설치 프로그램 예제 (Visual C++ Redistributable):**

```nsh
!macro NSIS_HOOK_POSTINSTALL
  ; Check if Visual C++ 2019 Redistributable is installed (via Windows Registry)
  ReadRegDWord $0 HKLM "SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64" "Installed"

  ${If} $0 == 1
    DetailPrint "Visual C++ Redistributable already installed"
    Goto vcredist_done
  ${EndIf}

  ; Install from bundled MSI if not installed
  ${If} ${FileExists} "$INSTDIR\resources\vc_redist.x64.msi"
    DetailPrint "Installing Visual C++ Redistributable..."
    ; Copy to TEMP folder and then execute installer
    CopyFiles "$INSTDIR\resources\vc_redist.x64.msi" "$TEMP\vc_redist.x64.msi"
    ExecWait 'msiexec /i "$TEMP\vc_redist.x64.msi" /passive /norestart' $0

    ; Check wether installation process exited successfully (code 0) or not
    ${If} $0 == 0
      DetailPrint "Visual C++ Redistributable installed successfully"
    ${Else}
      MessageBox MB_ICONEXCLAMATION "Visual C++ installation failed. Some features may not work."
    ${EndIf}

    ; Clean up setup files from TEMP and your installed app
    Delete "$TEMP\vc_redist.x64.msi"
    Delete "$INSTDIR\resources\vc_redist.x64.msi"
  ${EndIf}

  vcredist_done:
!macroend
```

**주요 고려 사항:**

- 좋은 습관은 항상 레지스트리 키나 파일 존재 여부를 확인하거나 Windows [where] 명령을 통해 종속성이 이미 설치되어 있는지 확인하는 것입니다.
- 설치 흐름을 방해하지 않으려면 `/passive`, `/quiet` 또는 `/silent` 플래그를 사용하십시오. `.msi` 파일에 대한 [msiexec] 옵션이나 앱별 플래그에 대한 설정 설명서를 확인하십시오.
- 사용자 장치를 다시 시작하는 설정의 경우 설치 중에 자동 시스템 재부팅을 방지하려면 `/norestart`를 포함하십시오.
- 애플리케이션 비대화를 방지하려면 임시 파일과 번들링된 설치 프로그램을 정리하십시오.
- 제거할 때 다른 애플리케이션과 종속성이 공유될 수 있음을 고려하십시오.
- 설치가 실패하면 의미 있는 오류 메시지를 제공하십시오.

`src-tauri/resources` 폴더에 종속성 설치 프로그램을 번들링하고 `tauri.conf.json`에 추가하여 번들링되도록 하고 설치 중에 `$INSTDIR\resources\`에서 액세스할 수 있도록 하십시오:

```json title="tauri.conf.json"
{
  "bundle": {
    "resources": [
      "resources/my-dependency.exe",
      "resources/another-one.msi"
    ]
  }
}
```

### 설치 모드

기본적으로 설치 프로그램은 현재 사용자에 대해서만 애플리케이션을 설치합니다.
이 옵션의 장점은 설치 프로그램을 실행하는 데 관리자 권한이 필요하지 않지만
앱이 `C:/Program Files` 대신 `%LOCALAPPDATA%` 폴더에 설치된다는 것입니다.

앱 설치를 시스템 전체에서 사용할 수 있도록 하려면(관리자 권한 필요)
[installMode]를 `perMachine`으로 설정할 수 있습니다:

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "nsis": {
        "installMode": "perMachine"
      }
    }
  }
}
```

또는 [installMode]를 `both`로 설정하여 사용자가 앱을 현재 사용자에 대해서만 설치할지 또는 시스템 전체에 설치할지 선택하도록 할 수 있습니다.
설치 프로그램을 실행하려면 관리자 권한이 필요합니다.

자세한 내용은 [NSISInstallerMode]를 참조하십시오.

### 국제화

NSIS 설치 프로그램은 다국어 설치 프로그램이므로 선택한 모든 번역이 포함된 단일 설치 프로그램이 항상 있습니다.

[`tauri.bundle.windows.nsis.languages`](/ko/reference/config/#languages) 속성을 사용하여 포함할 언어를 지정할 수 있습니다.
NSIS가 지원하는 언어 목록은 [NSIS GitHub 프로젝트][the NSIS GitHub project]에서 확인할 수 있습니다.
몇 가지 [Tauri 관련 번역][Tauri-specific translations]이 필요하므로 번역되지 않은 텍스트가 보이면 [Tauri의 메인 리포지토리][Tauri's main repo]에서 기능 요청을 자유롭게 여십시오.
[사용자 지정 번역 파일](/ko/reference/config/#customlanguagefiles)을 제공할 수도 있습니다.

기본적으로 운영 체제 기본 언어가 설치 프로그램 언어를 결정하는 데 사용됩니다.
설치 프로그램 내용이 렌더링되기 전에 언어 선택기를 표시하도록 설치 프로그램을 구성할 수도 있습니다:

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "nsis": {
        "displayLanguageSelector": true
      }
    }
  }
}
```

### 최소 Webview2 버전

앱에 최신 Webview2 버전에서만 사용할 수 있는 기능(예: 사용자 지정 URI 체계)이 필요한 경우 Windows 설치 프로그램에
현재 Webview2 버전을 확인하고 대상 버전과 일치하지 않으면 Webview2 부트스트래퍼를 실행하도록 지시할 수 있습니다.

```json title="tauri.conf.json"
{
  "bundle": {
    "windows": {
      "nsis": {
        "minimumWebview2Version": "110.0.1531.0"
      }
    }
  }
}
```
