## 설정

### Android

Android에서 링크로 앱을 여는 방법에는 두 가지가 있습니다:

1. **앱 링크 (http/https + 호스트, 검증됨)**
   [앱 링크](https://developer.android.com/training/app-links#android-app-links)의 경우, 주어진 형식으로 텍스트 응답을 반환해야 하는 `.well-known/assetlinks.json` 엔드포인트가 있는 서버가 필요합니다:

```json title=".well-known/assetlinks.json"
[
  {
    "relation": ["delegate_permission/common.handle_all_urls"],
    "target": {
      "namespace": "android_app",
      "package_name": "$APP_BUNDLE_ID",
      "sha256_cert_fingerprints": [
        $CERT_FINGERPRINT
      ]
    }
  }
]
```

여기서 `$APP_BUNDLE_ID`는 [`tauri.conf.json > identifier`]에 정의된 값에서 `-`를 `_`로 바꾼 값이고,
`$CERT_FINGERPRINT`는 앱의 서명 인증서의 SHA256 지문 목록입니다.
자세한 내용은 [Android 앱 링크 확인](https://developer.android.com/training/app-links/verify-android-applinks#web-assoc)을 참조하십시오.

2. **사용자 지정 URI 체계 (호스트 필요 없음, 검증 없음)**
   `myapp://...`와 같은 URI의 경우 파일을 호스팅하지 않고도 사용자 지정 체계를 선언할 수 있습니다. 모바일 구성에서 `scheme` 필드를 사용하고 `host`를 생략하십시오.

### iOS

iOS에서 링크로 앱을 여는 방법에는 두 가지가 있습니다:

1. **유니버설 링크 (https + 호스트, 검증됨)**
   [유니버설 링크][universal links]의 경우, 주어진 형식으로 JSON 응답을 반환해야 하는 `.well-known/apple-app-site-association` 엔드포인트가 있는 서버가 필요합니다:

```json title=".well-known/apple-app-site-association"
{
  "applinks": {
    "details": [
      {
        "appIDs": ["$DEVELOPMENT_TEAM_ID.$APP_BUNDLE_ID"],
        "components": [
          {
            "/": "/open/*",
            "comment": "Matches any URL whose path starts with /open/"
          }
        ]
      }
    ]
  }
}
```

:::note
응답 `Content-Type` 헤더는 `application/json`이어야 합니다.

`.well-known/apple-app-site-association` 엔드포인트는 HTTPS를 통해 제공되어야 합니다.
localhost를 테스트하려면 자체 서명된 TLS 인증서를 사용하여 iOS 시뮬레이터에 설치하거나 [ngrok]과 같은 서비스를 사용할 수 있습니다.
:::

여기서 `$DEVELOPMENT_TEAM_ID`는 `tauri.conf.json > tauri > bundle > iOS > developmentTeam` 또는 `TAURI_APPLE_DEVELOPMENT_TEAM` 환경 변수에 정의된 값이고, `$APP_BUNDLE_ID`는 [`tauri.conf.json > identifier`]에 정의된 값입니다.

도메인이 앱 연결을 노출하도록 올바르게 구성되었는지 확인하려면 다음 명령을 실행하고 `<host>`를 실제 호스트로 바꾸십시오:

```sh
curl -v https://app-site-association.cdn-apple.com/a/v1/<host>
```

자세한 내용은 [applinks.details](https://developer.apple.com/documentation/bundleresources/applinks/details-swift.dictionary)를 참조하십시오.

2. **사용자 지정 URI 체계 (호스트 필요 없음, 검증 없음)**
   `myapp://...`와 같은 URI의 경우 모바일 구성에서 `"appLink": false`로 사용자 지정 체계를 선언할 수 있습니다(또는 생략). 플러그인은 앱의 Info.plist에 적절한 `CFBundleURLTypes` 항목을 생성합니다. `.well-known` 파일이나 HTTPS 호스트는 필요하지 않습니다.

### 데스크톱

Linux 및 Windows에서 딥 링크는 새 앱 프로세스에 대한 명령줄 인수로 전달됩니다.
딥 링크 플러그인은 이벤트를 수신하는 고유한 앱 인스턴스를 선호하는 경우 [싱글 인스턴스][single instance] 플러그인과 통합됩니다.

- 먼저 싱글 인스턴스 플러그인에 `deep-link` 기능을 추가해야 합니다:

```toml title="src-tauri/Cargo.toml"
[target."cfg(any(target_os = \"macos\", windows, target_os = \"linux\"))".dependencies]
tauri-plugin-single-instance = { version = "2.0.0", features = ["deep-link"] }
```

- 그런 다음 항상 등록하는 첫 번째 플러그인이어야 하는 싱글 인스턴스 플러그인을 구성하십시오:

```rust title="src-tauri/lib.rs"
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    let mut builder = tauri::Builder::default();

    #[cfg(desktop)]
    {
        builder = builder.plugin(tauri_plugin_single_instance::init(|_app, argv, _cwd| {
          println!("새 앱 인스턴스가 {argv:?}와 함께 열렸고 딥 링크 이벤트가 이미 트리거되었습니다");
          // 런타임에 딥 링크 체계를 정의할 때 여기서 `argv`도 확인해야 합니다
        }));
    }

    builder = builder.plugin(tauri_plugin_deep_link::init());
}
```

:::caution
사용자는 인수에 URL을 포함하여 수동으로 가짜 딥 링크를 트리거할 수 있습니다.
Tauri는 이를 완화하기 위해 명령줄 인수를 구성된 체계와 일치시키지만, URL이 예상 형식과 일치하는지 여부는 여전히 확인해야 합니다.

즉, Tauri는 정적으로 구성된 체계에 대해서만 딥 링크를 처리하며, 런타임에 등록된 체계는 [`Env::args_os`]를 사용하여 수동으로 확인해야 합니다.
:::

## 설정

`tauri.conf.json > plugins > deep-link`에서 애플리케이션과 연결하려는 모바일 도메인/체계 및 데스크톱 체계를 구성하십시오.

### 예제

**모바일의 사용자 지정 체계 (서버 필요 없음):**

```json title="tauri.conf.json"
{
  "plugins": {
    "deep-link": {
      "mobile": [
        {
          "scheme": ["ovi"],
          "appLink": false
        }
      ]
    }
  }
}
```

이것은 Android 및 iOS에서 `ovi://*` 체계를 등록합니다.

**앱 링크 / 유니버설 링크 (검증된 https + 호스트):**

```json
{
  "plugins": {
    "deep-link": {
      "mobile": [
        {
          "scheme": ["https"],
          "host": "your.website.com",
          "pathPrefix": ["/open"],
          "appLink": true
        }
      ]
    }
  }
}
```

이것은 `https://your.website.com/open/*`을 앱/유니버설 링크로 등록합니다.

**데스크톱 사용자 지정 체계:**

```json
{
  "plugins": {
    "deep-link": {
      "desktop": {
        "schemes": ["something", "my-tauri-app"]
      }
    }
  }
}
```

## 사용법

딥 링크 플러그인은 JavaScript와 Rust 모두에서 사용할 수 있습니다.

### 딥 링크 수신 대기

<Tabs syncKey="lang">
  <TabItem label="JavaScript">

앱이 실행되는 동안 딥 링크가 앱을 트리거하면 `onOpenUrl` 콜백이 호출됩니다. 앱이 딥 링크를 통해 열렸는지 감지하려면 앱 시작 시 `getCurrent`를 사용하십시오.

```javascript
import { getCurrent, onOpenUrl } from '@tauri-apps/plugin-deep-link';
// `"withGlobalTauri": true`를 사용할 때, 다음을 사용할 수 있습니다:
// const { getCurrent, onOpenUrl } = window.__TAURI__.deepLink;

const startUrls = await getCurrent();
if (startUrls) {
  // 앱이 딥 링크를 통해 시작되었을 가능성이 높습니다.
  // getCurrent의 반환 값은 onOpenUrl이 트리거될 때마다 업데이트됩니다.
}

await onOpenUrl((urls) => {
  console.log('deep link:', urls);
});
```

  </TabItem>
  <TabItem label="Rust">

앱이 실행되는 동안 딥 링크가 앱을 트리거하면 플러그인의 `on_open_url` 클로저가 호출됩니다. 앱이 딥 링크를 통해 열렸는지 감지하려면 앱 시작 시 `get_current`를 사용하십시오.

```rust title="src-tauri/src/lib.rs"
use tauri_plugin_deep_link::DeepLinkExt;

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_deep_link::init())
        .setup(|app| {
            // get_current의 반환 값은 on_open_url이 트리거될 때마다 업데이트됩니다.
            let start_urls = app.deep_link().get_current()?;
            if let Some(urls) = start_urls {
                // 앱이 딥 링크에 의해 시작되었을 가능성이 높습니다.
                println!("deep link URLs: {:?}", urls);
            }

            app.deep_link().on_open_url(|event| {
                println!("deep link URLs: {:?}", event.urls());
            });
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

  </TabItem>
</Tabs>

:::note
URL 열기 이벤트는 macOS API와 호환되도록 요청된 URL 목록과 함께 트리거되지만, 대부분의 경우 앱은 단일 URL만 수신합니다.
:::

### 런타임에 데스크톱 딥 링크 등록

[설정](#설정) 섹션에서는 애플리케이션에 대한 정적 딥 링크 체계를 정의하는 방법을 설명합니다.

Linux 및 Windows에서는 `register` Rust 함수를 통해 런타임에 애플리케이션과 체계를 연결할 수도 있습니다.

다음 스니펫에서는 런타임에 `my-app` 체계를 등록합니다. 앱을 처음 실행한 후 운영 체제는 `my-app://*` URL을 애플리케이션으로 엽니다:

```rust title="src-tauri/src/lib.rs"
use tauri_plugin_deep_link::DeepLinkExt;

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_deep_link::init())
        .setup(|app| {
            #[cfg(desktop)]
            app.deep_link().register("my-app")?;
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

:::note
기본적으로 딥 링크는 앱이 설치될 때만 등록되므로 런타임에 딥 링크를 등록하는 것은 Linux 및 Windows 개발에 유용할 수 있습니다.

AppImage 설치는 AppImage를 운영 체제와 통합하기 위해 AppImage 런처가 필요하므로 복잡할 수 있습니다.

런타임에 딥 링크를 등록하는 것이 선호될 수 있으므로 Tauri에는 런타임에 정적으로 구성된 모든 딥 링크를 강제로 등록하는 도우미 함수도 포함되어 있습니다.
이 함수를 호출하면 개발 모드에서도 딥 링크가 등록됩니다:

```rust
#[cfg(any(target_os = "linux", all(debug_assertions, windows)))]
{
  use tauri_plugin_deep_link::DeepLinkExt;
  app.deep_link().register_all()?;
}
```

:::

## 테스트

애플리케이션에 대한 딥 링크를 테스트할 때 몇 가지 주의 사항이 있습니다.

### 데스크톱

딥 링크는 데스크톱에 설치된 애플리케이션에 대해서만 트리거됩니다.
Linux 및 Windows에서는 [`register_all`] Rust 함수를 사용하여 이를 우회할 수 있습니다. 이 함수는 구성된 모든 체계를 등록하여 현재 실행 파일을 트리거합니다:

```rust title="src-tauri/src/lib.rs"
use tauri_plugin_deep_link::DeepLinkExt;

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_deep_link::init())
        .setup(|app| {
            #[cfg(any(windows, target_os = "linux"))]
            {
                use tauri_plugin_deep_link::DeepLinkExt;
                app.deep_link().register_all()?;
            }
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

:::note
Linux에서 딥 링크를 지원하는 AppImage를 설치하려면 AppImage를 운영 체제와 통합하기 위해 AppImage 런처가 필요합니다.
`register_all` 함수를 사용하면 사용자가 외부 도구를 사용할 필요 없이 즉시 딥 링크를 지원할 수 있습니다.

AppImage가 파일 시스템의 다른 위치로 이동하면 실행 파일에 대한 절대 경로를 활용하므로 딥 링크가 무효화되어 런타임에 체계를 등록하는 것이 훨씬 더 중요해집니다.

자세한 내용은 [런타임에 데스크톱 딥 링크 등록](#런타임에-데스크톱-딥-링크-등록) 섹션을 참조하십시오.
:::

:::caution
macOS에서는 런타임에 딥 링크를 등록할 수 없으므로 딥 링크는 `/Applications` 디렉토리에 설치해야 하는 번들 애플리케이션에서만 테스트할 수 있습니다.
:::

#### Windows

Windows에서 딥 링크를 트리거하려면 브라우저에서 `<scheme>://url`을 열거나 터미널에서 다음 명령을 실행할 수 있습니다:

```sh
start <scheme>://url
```

#### Linux

Linux에서 딥 링크를 트리거하려면 브라우저에서 `<scheme>://url`을 열거나 터미널에서 `xdg-open`을 실행할 수 있습니다:

```sh
xdg-open <scheme>://url
```

### iOS

iOS에서 앱 링크를 트리거하려면 브라우저에서 `https://<host>/path` URL을 열 수 있습니다. 시뮬레이터의 경우 `simctl` CLI를 활용하여 터미널에서 직접 링크를 열 수 있습니다:

```sh
xcrun simctl openurl booted https://<host>/path
```

### Android

Android에서 앱 링크를 트리거하려면 브라우저에서 `https://<host>/path` URL을 열 수 있습니다. 에뮬레이터의 경우 `adb` CLI를 활용하여 터미널에서 직접 링크를 열 수 있습니다:

```sh
adb shell am start -a android.intent.action.VIEW -d https://<host>/path <bundle-identifier>
```

## 권한

기본적으로 잠재적으로 위험한 모든 플러그인 명령과 범위는 차단되어 액세스할 수 없습니다. 이를 활성화하려면 `capabilities` 설정에서 권한을 수정해야 합니다.

자세한 내용은 [기능 개요](/security/capabilities/) 및 [단계별 가이드](/learn/security/using-plugin-permissions/)를 참조하여 플러그인 권한을 사용하십시오.

```json title="src-tauri/capabilities/default.json" ins={9}
{
  "$schema": "../gen/schemas/mobile-schema.json",
  "identifier": "mobile-capability",
  "windows": ["main"],
  "platforms": ["iOS", "android"],
  "permissions": [
    // 일반적으로 딥 링크 이벤트를 수신하려면 core:event:default가 필요합니다.
    "core:event:default",
    "deep-link:default"
  ]
}
```
